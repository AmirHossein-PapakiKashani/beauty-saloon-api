درس ۱: حلقه headless یعنی چه؟

یک برداشت ذهنی — قبل از هر دستور terminal

تشبیه: کارگاه نرم‌افزار

اسکریپت PowerShell = مدیر کارگاه (تصمیم می‌گیرد «الان کدام use case»)
current-prompt.txt = برگهٔ کار برای کارگر
Cline / OpenCode / AGY = کارگر (کد می‌زند)
dotnet test = بازرس (فقط او می‌گوید «تمام شد» یا نه)

پنج فاز (Hybrid C)

  1. Select — از queue.json یک use case pending با وابستگی‌های سبز.
  2. Enrich — پرامپت غنی در state/current-prompt.txt (الان از template ساده).
  3. Inject — همان پرامپت به CLI headless داده می‌شود.
  4. Verify — dotnet test؛ تا سبز نشود جلو نرو.
  5. Close — completed در queue + use case بعدی.

«فعال کردن Cline» یعنی چه؟

نه تنظیم خاصی در VS Code. یعنی از ترمینال بگویی:

cline -y "ماموریت از current-prompt.txt"

فلگ -y = headless + auto-approve (بدون UI، بدون تأیید دستی).

وضعیت پروژهٔ تو الان

فازهای ۱، ۲، ۴، ۵ در run-backend-cycle.ps1 هست. فاز ۳ (Inject) هنوز stub است — یعنی باید یک بار دستی Inject را یاد بگیری، بعد wire کنی.
